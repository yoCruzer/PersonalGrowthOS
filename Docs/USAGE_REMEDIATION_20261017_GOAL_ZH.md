## 1. 一个完整目标

让随心log在新增待办、今天、成长及其回顾页面中具有一致的信息层级、清楚的动作含义和可信的统计；解决九项反馈，并一起处理时间投入 V1 中同源的入口、状态、关闭文案、统计范围、长列表和重复计算问题。保留轻量、离线、个人日常使用的定位。

完成含义：实现全部必选项 → 受影响验证 → 集中组合验收 → 真正独立只读 review → 范围内修复复核 → 普通 push 与新 Draft PR → 明确下一步真机清单。只完成计划、第一阶段、原型图或第一轮 review 均不算完成。

用户本次要求定义一个连续执行的大批次；下列阶段是内部检查点，不是逐阶段等待批准的停点。旧 CURRENT 中“时间投入仅等待设备门禁、不开新功能”是上一批交接边界，本次新需求在新分支替代该停点；旧的 FAIL / SKIP / NOT_RUN 事实和私人数据、签名、发行边界继续有效。无需修改 DEVELOPMENT_CONTRACT 的长期规则。

## 2. 启动与分支保护

1. 按 AGENTS.md 读取 INDEX、现存 Foundation、DEVELOPMENT_CONTRACT、CURRENT_STATE/CURRENT_TASK，然后读取本组规格及相关现行代码、局部指令、测试。区分当前授权与下方历史交接。
2. 只读核对 repo、worktree、dirty、branch/upstream 和 PR。保留原工作区所有未知改动，不 stash/reset/restore/clean，不吸收进本任务。使用独立 worktree。
3. 验证 BASE 是 GOAL_SHA 祖先，`BASE..GOAL_SHA` 累计差异只含本组三份 Markdown 及 `Docs/INDEX.md`、`Docs/V1_SCOPE.md`、`Docs/CURRENT_STATE.md`、`Docs/CURRENT_TASK.md`。规划输入没有产品、工程、测试变更；后续规划修订可追加文档提交，不要求每次 GOAL_SHA 直接以 BASE 为父。
4. 从固定 GOAL_SHA 创建新产品分支和独立 worktree；不把实现推到规划分支或时间投入旧分支。若同名产品分支/worktree/PR 已存在，核验祖先、任务身份及未完成工作后安全续接，不删除重建、不重写历史。
5. 新 Draft PR 叠加到 `codex/time-investment-v1`。如果启动时其 head 已推进，先记录新旧 SHA 和实际差异，继续固定输入下不冲突的工作；集成必要修复应明确核验并记录，不盲目 pull/rebase、不遗漏 F1、不切换到过期 main。旧 PR 的 head/base/状态保留。
6. 阶段 0 只做轻量影响分析：确认 UI 接点、重复/提醒模型、共享通知协调器、体重日期模型、时间投入统计和 V14/v10 迁移备份链；据实际字段设计安排最少必要的追加版本。不在起点重跑旧全量测试。

## 4. 范围与不变量

- 详细产品规则以 DESIGN 1.0 为准，验收 IDs 见 ACCEPTANCE。原九项与时间投入 T1–T8 均有追踪行，不依赖旧聊天或截图顺序。
- 保持 Today / Timeline / Record / Growth / Library 五 Tab、Record 图文记录、Today 原有功能优先级、旧快捷输入与独立草稿；共享布局只共享共同结构，不做全 App 通用框架重写。
- 时间投入仍是独立模块；保护 `ContinuousClock`、`continuous-v1:` 进程域、50 ms / 18 h 保护、暂停不累计、倒计时封顶/显式继续和跨进程复核；保护已关闭的 R1–R3：不残留已消费正文、不复活删除/放弃记录、失败保留输入、精确时间替换须明确确认。
- 时间投入正式事实、参与者隔离、原时区跨日分摊、Session 次数去重、惰性默认“我”、空库恢复和检查点备份规则保持。Todo AlarmKit 不扩展成时间投入到点响铃或新的后台计时能力。
- 允许本目标必需的最小模型/追加 Schema/备份版本、BMI 本地设置、AlarmKit 系统框架接入/用途说明/必要 App Intent 接线；保留历史模型校验和、原身份、主库和既有签名配置。正常的公开 SDK 接入和本任务可逆工程调整不需逐项再问批准；若实际需额外付费、账号或发布级能力，先说明具体阻塞并完成其余可执行事项。
- 不增加 AI、联网分析、HealthKit、减重处方、家庭/孩子 UI、云同步、复杂任务优先级/项目管理、节假日调休日历、复杂番茄钟、时间预算、Live Activity 倒计时/贪睡或新 Widget。BMI 先提供中国成人与 WHO 常用成人参照，不扩展为全球健康平台。
- 不改主 Bundle ID、App Group、原存储位置、Share/ImportantDaysWidget 身份、版本号、签名/发布配置或 CI 发布流；不改写历史模型以规避迁移，不清库，不放宽空库恢复保护，不忽略新版本未知枚举。

## 5. 验证和独立审查的节奏

阶段内只跑与行为改动相关的 Unit、服务/磁盘/备份和必要 UI；文案/间距无需机械补实现镜像测试。新增统计、重复算法和提醒生命周期用可复现边界数据；迁移或共享协调器变更尽早验证实际生产路径。

功能与主要发现收敛后，D 阶段做一次集中全量 Unit 和关键组合 UI，固定干净产品/测试 SHA 完成 Debug Simulator 与 unsigned generic iOS Release 构建及实际 App/Share/Widget 身份、provenance 检查。修复后按真实影响补验；只有共享持久化/导入/调度等风险证据要求时才扩大重跑。不逐阶段跑完整旧全套，不在仅最终文档提交后反复构建，不并行占用多个 Xcode 测试队列。

至少一名真正独立、只读的 agent/会话审查固定提交、完整 diff、关键生产调用链和原始验证证据。可早审迁移/提醒设计，最终统一审查用户流程；实现者复现并限定修复，再由独立 reviewer 核对关闭。关闭范围内确认的 P0/P1，以及影响必选路径、数据可信度或旧数据保护的 P2。不以主 agent 改称 reviewer 冒充独立审查，也不将 UI 图/静态阅读当成原生运行证据。

历史验证可据固定 SHA、未变更代码与依赖影响矩阵复用；不把不同轮次计数相加成一次全绿。记录每轮精确命令/selector、产品/测试 SHA、通过/失败/跳过数、日志位置；保留失败与警告。新出现的回归不能借历史限制跳过。真正环境阻塞不循环空跑，先完成可安全推进的其余阶段。

所有验证使用合成数据和任务专用模拟器/临时库。真实 iPhone 锁屏/硬件睡眠、AlarmKit 静音/专注实际递送、私人库不卸载覆盖、签名、实际 Widget/Photos/VoiceOver/飞行模式等分开列为 Owner 设备门禁；未做就写 NOT_RUN。既有设备 Gate 不阻挡已授权整改编码，模拟器或桩也不能替代其通过证明。

## 6. 交付与最终停点

在新产品分支按阶段做清楚的 commit、普通 push，创建/更新本目标唯一的新 Draft PR，base 为时间投入分支；不为每阶段创建一组叠加 PR。保留旧 PR，不 merge/force/tag/Archive/TestFlight，不自行安装或操作 Owner 手机/私人库。

维护精简交付文档：本组 ACCEPTANCE 追加实际证据；新建 `USAGE_REMEDIATION_20261017_EXECUTION.md` 记录阶段/命令/失败/影响矩阵，`USAGE_REMEDIATION_20261017_REVIEW_ZH.md` 记录独立审查与闭环；CURRENT 两份文件更新当前事实和下一边界。规格正文不为凑通过而放宽，历史证据原样保留。

最终交接列出固定 BASE / GOAL_SHA、实际 branch/base/head、产品/测试提交、最终交付提交、阶段与原反馈映射、实际测试及剩余设备清单，并核对远端和本任务工作树。没有独立 reviewer 则如实 `REVIEW_BLOCKED`；本地核心实现或可执行必选验证未完成则不得标完成。只在全部本地必选实现、验证和独立审查完成后停 `READY_FOR_OWNER_DEVICE_GATE`，设备未做的项目保持原状态。

默认中文沟通。正常实现选择、受影响测试、范围内修复与普通推送自主完成，不在计划、中期提交或首轮 review 后停下来问是否继续。
