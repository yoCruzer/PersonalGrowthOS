## 1. 共用合成样本与可复算结果

固定一个家庭范围、人民币，所有名称和金额均为人工测试数据。初始盘点日 2026-09-30：

| 项目 | 性质 | 金额（元） |
| --- | --- | ---: |
| 测试银行账户 | 资产/现金存款 | 100,000.00 |
| 测试投资账户 | 资产/投资 | 200,000.00 |
| 测试住房 | 资产/房产，估算 | 2,000,000.00 |
| 测试车辆 | 资产/车辆，估算 | 100,000.00 |
| 测试房贷 | 负债/房贷 | 1,000,000.00 |
| 测试信用卡 | 负债/信用卡 | 10,000.00 |

总资产 **2,400,000.00**，总负债 **1,010,000.00**，净资产 **1,390,000.00**。房产估值日期可设为 2026-06-30，其他值日期不晚于盘点日。

各反例从同一基准独立派生，避免串联修改导致预期含糊：

- 银行转投资 10,000：银行 90,000，投资 210,000，净资产仍 1,390,000。
- 用现金还本金 20,000、不含利息手续费：银行 80,000，房贷 980,000，资产 2,380,000、负债 990,000，净资产仍 1,390,000。
- 房贷未知：已知资产 2,400,000、已知负债 10,000，**完整净资产待补全**，不得显示成 2,390,000 的完整净资产。
- 单独只有负债 10,000 且明确本次无计入资产：净资产 −10,000，正常绘图。
- 在基准前一份记录遗漏住房，下一份补录它：值可改变，但范围提示明确，不能说赚了 2,000,000。

视觉样本另提供 12 次真实日历日期（至少一个缺月、一条缺测、一处范围变化）、长项目名、极大金额、零、负值和空库。UI 文档里的金额仅是排版示例，断言以这里及对应场景的明确数据为准。

## 3. 精简执行节奏和结果写法

阶段 A 跑金额、草稿最短路径与旧库/备份接缝；阶段 B 随改动补日期、历史、恢复与隐私；阶段 C 完成集中截图和独立 Review。不要在每阶段重新跑历史完整套件。

最终复用现有 CI 的 unsigned Release、完整 Unit、5 条关键 smoke。新增资产核心 UI 可定向本地运行，无需为本模块重构 CI 或添加一个默认全量 UI 矩阵。现有旧 schema/旧包版本测试继续由必要共享回归与最终 Unit 覆盖，不为本期另造所有年代版本的大型组合矩阵。

每条实际结果填写：状态（PASS/FAIL/SKIP/NOT_RUN）、固定产品/测试 SHA、命令/selector、结果数量、证据路径，以及它不能证明的部分。保留失败轮与修复后重跑，不把历史基线通过写成新提交通过。纯文档变更可以说明相同产品树并复用，不为“最后一个 commit 也绿”反复烧测试。

独立审查读取固定 diff、关键生产调用链、真实测试和原始截图，确认必须修项已关闭。视觉审查必须回答 UI 文档的五个问题；不能只写“风格不错”。

## 4. Owner 的小范围试用清单

进入本清单前，核心功能、本地可执行验收、必选 CI 与独立审查已经完成。执行者只交付清单与证据，不自动操作 Owner 设备或真实数据。

| 任务 | Owner 要判断的体验 | 状态 |
| --- | --- | --- |
| 第一次盘点 | 无讲解能否找到入口，录入几项资产/负债，理解人民币、估算和未填；没有 demo 式杂乱或不协调控件 | NOT_RUN |
| 再次盘点 | 用约 10 个合成项目，只更新 2–3 项，其余明确沿用；是否能几分钟完成，键盘/下一项/保存顺手 | NOT_RUN |
| 回看与更正 | 一眼能否读出时点和净资产；点趋势到明细；改错一个旧值后理解变化，不误认为投资收益 | NOT_RUN |
| 真机隐私 | 开启设备认证、取消/失败/系统密码回退；后台 App 预览、回前台、深链和导出；金额隐藏与真实 VoiceOver 无泄露 | NOT_RUN |
| 安全升级与迁移 | 按既有 Owner 安装/备份流程确认覆盖升级旧内容正常；自行选择数据和目的地做整包导出/恢复，不由自动化触碰私人库 | NOT_RUN |

首轮观察应区分两个成本：首次整理全部家庭项目可能较长；日后重复确认才是“几分钟”的主要验证对象。记录实际操作时间、迷失位置和不理解的状态，不把一个人的试用编成市场转化率。

既有 D1–D4、真实相机/AlarmKit/Safari/Share/低空间等历史设备项目继续保留原清单和证据；本表不把它们重新声明为通过，也不无条件要求全部重做。
