# 随心 log · 家庭资产 V1 界面与交互规格

- 版本：1.0（2026-11-01）；与 [产品契约](HOUSEHOLD_ASSETS_V1_DESIGN_ZH.md) 和 [Goal](HOUSEHOLD_ASSETS_V1_GOAL_ZH.md) 同版执行。
- Owner 要求：**界面风格和习惯统一，有设计感，不能一眼像 demo。** 本文件把这项要求变成可检查的页面层级、操作和真实截图标准。
- 依据：固定基线 `5827c657095945aff30b2250b20bae104c7b0357` 的 SwiftUI 源码及真实浅/深色 PNG。当前没有另一个正式品牌色或设计 token 系统，不能假称已有。

## 1. 设计方向：现有原生语言，明确的信息层级

沿用随心 log 的系统分组列表、系统大标题、主次文字、accent 操作色、原生导航及 sheet 编辑。设计投入放在金额排版、留白、日期与数据状态、连续录入和图表下钻上。它应该像随心 log 自然长出来的一页。

不重新设计五 Tab、全 App 字体、导航栏、习惯计数器或已有模块，不搭建一套新的通用组件库。模块内可提取真正重复的金额、摘要、明细行和图表选择视图。

### 可直接复用的现有约定

| 现有实现 | 新模块用法 |
| --- | --- |
| `AppShell.swift` 的 `ModuleEntryRow` | 成长入口复用；20 pt 图标、24 pt 图标列、12 pt 间距，标题/副标题 3 pt；辅助功能字号尾值移入正文列 |
| `GrowthEmptyStateAddButton` | 首次“开始第一次盘点”，使用现有 prominent / large / 最小 44 pt 触控方式 |
| `Growth/HabitViews.swift` 的 `GrowthView` | 在现有成长模块列表增加同级入口；入口统计只读，不为默认值写库 |
| `Weight/WeightViews.swift` 的 Swift Charts 及历史编辑 | 借鉴真实日期、点选、列表替代路径和 sheet；金额计算独立 |
| 系统 `List` / `Form` / `NavigationStack` | 统一页面底色、分组、分隔线、导航返回、工具栏与取消/保存习惯 |
| `.primary` / `.secondary` / `Color.accentColor` | 主数字用主文字色、动作与主趋势用 accent；深色自动适配 |

当前 AccentColor 没有自定义 RGB。不要把习惯计数器专门修过的局部颜色当成全 App 品牌色复制。避免多张等权彩色 KPI 卡、渐变资产背景、装饰大图标、排行榜式涨跌和层层嵌套卡片。

## 2. 导航与页面职责

| 页面 | 解决的问题 | 主操作 |
| --- | --- | --- |
| 成长入口 | 从现有习惯找到模块 | “家庭资产”；不透露金额 |
| 家庭资产总览 | 最近记录多少，长期怎么变 | 记录盘点 / 继续盘点 |
| 盘点编辑 | 本次哪些项目更新，哪些沿用 | 保存盘点；稍后继续 |
| 盘点详情与历史 | 还原某日组成、解释变化 | 更正；用户主动关联记录 |
| 项目管理/详情 | 管理名称分类和归档，查看某项目历史 | 添加/编辑/归档项目 |
| 模块隐私与导出 | 控制显示、设备认证及数据取出 | 金额隐藏、设备认证、CSV |

成长入口建议标题“家庭资产”、副标题“定期盘点，看见变化”、线性 SF Symbol `chart.pie`；尾部“已盘点 X 次”或“尚未盘点”。不使用净资产、涨跌或草稿数替代正式次数。读取失败显示可重试状态，不能报 0 次。

不增加模块自己的底部 Tab。历史和项目管理可从总览的列表行/工具栏更多菜单进入；需要历史日期时用同样的导航层级，返回位置和滚动状态合理保留。

## 3. 总览：一眼找到净资产、日期和下一步

首屏内容顺序如下；不为塞进一屏缩小文字或触控区：

1. 系统大标题“家庭资产”，工具栏有金额显示切换和更多操作。
2. 最近正式盘点摘要；有草稿时，摘要仍是正式数据，主动作改“继续盘点”。
3. 一个明确的主操作“记录盘点”。
4. 净资产趋势。
5. 资产结构、明细和历史入口。

### 摘要排版

一个系统分组容器内左对齐，避免三个大数字争夺注意。日期、标签、主金额、变化说明和次级小计组成一个 VStack 摘要行；不要让每个 Text 都成为独立 List 行，在金额中间插入一串分隔线；无需为此新建全局 Card 体系。

| 内容 | 视觉层级 |
| --- | --- |
| 最近盘点 · 2026年10月31日 | subheadline，secondary |
| 净资产 | subheadline，主/次文字保持清楚 |
| ¥1,268,500.00 | largeTitle/title、semibold、monospacedDigit；全页唯一主要金额 |
| 较上次增加 ¥12,300；比较日期 | 普通正文/次级说明，不做涨跌奖励色 |
| 总资产 / 总负债 | 并列次级标签与 body/title3 金额；大字时纵排 |
| 含估算或沿用；未知项提示 | 靠近金额，用文字表达真实状态，不藏在页底 |

从现有系统 inset 起步，摘要内部使用约 8/12/16 pt 的自然间距；Section 之间靠系统间距区分。不要为了精确像素另设一套屏幕宽度常量，最终以真实设备布局为准。

没有完整净资产时，主位显示“待补全”，下面显示“负债有 1 项未知”等具体原因；资产/负债各按自身完整性标“总额”或“已知小计”。不能在主位放一个看似准确的已知差额。首次记录写“首次盘点，暂无比较”；范围改变写“纳入项目有变化，暂不比较”。

金额不省略成 `1,268,…`，也不为了放下而缩成很小的字。先把币种与金额、并列小计改为纵向；极大金额需要紧凑展示时明确写“约”和“万元/亿元”，并提供完整金额的可达文字详情。输入、快照明细和导出始终保留精确值。未隐藏时 VoiceOver 读完整金额；隐藏时不读财务数字。

## 4. 图表：读得懂，也能查得回去

### 趋势

- 默认一条净资产主线；通过系统 Picker/菜单切到负债，复用同一图表区域，不默认叠三条线。
- 范围为近 6 个月、近 1 年、全部。日期轴按真实间隔，直线约 2 pt，真实盘点处有点；无平滑、面积装饰或虚构日数据。
- 绘图区约 200–240 pt 起步；轴标签和状态说明在绘图区外自然增长。纵轴明确元/万元等单位，约 3–5 个易读刻度；负净资产正常显示负值和零线。
- 点选后，在预留的文字区域展示日期、金额、估算/沿用状态及“查看这次盘点”，避免气泡遮挡或越界。选中不重新缩放纵轴。
- 连线使用产品契约里与差额相同的按指标可比条件。缺测不画虚假的净资产点、不跨它连接；统计范围变化保留两个真实点但断开，并在点选与历史行说明。无记录月份不补零；连接线只辅助阅读，不提供未记录日期的推算值。
- 同一数据由历史列表提供可达路径，支持 VoiceOver；操作不能只靠长按、拖动或辨别颜色。

### 资产结构

首版选横向条形与文字明细，不同时再做圆环。每行是分类名、金额、占比及次行条形；六个固定分类可按金额排序，但不能改变类别含义。标签和金额承担主要信息，单一 accent 即可，不依赖彩虹图例。

总览摘要和结构固定为日期最新的正式盘点，结构标题注明“截至某日”；趋势点选只改变点选摘要，不切换总览结构。历史结构在“查看这次盘点”的详情中展示。点击分类携带该结构明确绑定的盘点 ID 进入同次明细，不重新查询项目最新值。未知资产存在时标题“已知资产构成”，未知项数就近展示。分母为零时给出零金额/待补全说明，隐藏无意义百分比。负债不混进资产条形相减。

## 5. 盘点编辑：几个动作完成一次更新

使用已有编辑页习惯的 sheet + NavigationStack。标题“记录盘点”或“更正盘点”；主保存动作在工具栏，关闭行为明确保留草稿。用户可以稍后继续，放弃另置次级菜单。

顶部是日期、人民币说明，以及简短状态行，例如“已更新/确认 8 项 · 待核对沿用 1 项 · 未知 1 项”。随后按资产和负债分组，再按需要细分类。不要把 schema、事务、完整性校验等实现术语放进页面。

### 单项输入行

清楚分开四个元素：

1. 项目名称及必要标签。
2. “上次 ¥23,500 · 9月30日”等来源提示。
3. 本次数值输入，货币单位始终可辨。
4. “本次填写／已确认沿用／沿用待核对／未知”短状态。

预填旧值不能自动表现为本次确认。给出“沿用上次”明确动作；有多项未变化时可执行“其余沿用上次”，结果摘要再次说明沿用数与未知数。估算切换和金额日期放在行详情中，默认不把表单拉成每项六行。

数字键盘提供“完成”，连续录入时提供上一项/下一项或同等顺手路径；最后一项不保留无效“下一项”。当前输入不被键盘遮挡，保存可达。编辑中不不断插入千分位移动光标；退出输入后再格式化。空白与零区别明确，非法金额就地说明。

空资产/负债分组给出“添加项目”及“本次没有需记录的资产/负债”；尚未考虑该分组时可保存为待补全，不能默认为无负债。

保存中的主动作防重复且有处理中反馈；失败保留表单和输入，错误与重试持续可见。成功回到该次盘点结果，以简短“盘点已保存”反馈结束，不弹庆祝动画。保存一个历史更正后不要无说明跳到最近日期。

行高以现有约 52–56 pt 单行、64–72 pt 双行作为起点，内容多时自然增高；操作目标至少 44×44 pt。长名称和辅助功能字号改为名称在上、金额在下，不能左右挤压。

## 6. 空态、异常和隐私都是正式页面

| 状态 | 表达与操作 |
| --- | --- |
| 空库 | 一句用途说明与“开始第一次盘点”；无示例资产、假折线、空图卡堆叠 |
| 仅草稿 | 提示“尚未完成第一次盘点”与“继续盘点”；草稿不作净资产事实 |
| 只有一次完整盘点 | 一个真实点、日期与金额，“再记录一次即可比较变化” |
| 范围无记录 | “这段时间没有盘点”，可切到全部 |
| 真正为零 | 明确 ¥0.00，与无记录、未知和失败不同 |
| 负净资产 | 正常数字和轴线，不用整屏红色或异常警告 |
| 未知或沿用 | 分别显示“待补全”和沿用状态，不把二者统称未更新 |
| 读取失败 | 保留页面结构、原因与重试；不回落成零/空库 |
| 金额隐藏 | 所有财务数值及图表改为中性占位；眼睛按钮状态明确 |
| 设备认证取消/失败 | 停在锁定页，用户可重试/返回；草稿不丢，金额不先闪现 |

隐藏金额包括主值、列表值、差额、分类占比、轴标签、选中详情和无障碍值；图表用“金额已隐藏”占位。显示/隐藏不应产生把旧财务内容带入过渡动画的闪烁。编辑需先明确显示金额。

资产页面后台遮挡与可选设备认证按产品契约实现。界面写“验证身份”或系统 Face ID/Touch ID 名称，不写“金融级保险箱”。导出页在用户生成文件前说明资产数据和文件未加密。

## 7. 深色、大字体、语言与可访问性

系统动态底色和主次文字成对使用，不硬编码白卡黑字。深色下网格线弱于数据线，选中/未选中、禁用/可用能辨；关键操作不依赖低透明蓝字。

主金额、日期、状态和保存按钮必须同时可读。辅助功能字号允许更多滚动和纵向重排，不要求最大字号仍一屏展示所有信息。避免固定行高、过度缩字和靠 Spacer 推掉信息。

中英文 String Catalog 完整；分类、状态、日期范围、错误、确认、金额格式和用途说明均可本地化，不露出 enum key。图表有文字摘要/历史列表，无障碍标签说明金额所属日期与状态；隐藏时不读出被遮挡数据。

## 8. 有边界的视觉验收

阶段 A 就做真实原生的总览与编辑纵向切片，先与相邻模块并排检查；发现布局方向不对时立即改。阶段 C 完成下列 **8 组、约 8–10 张**关键截图，避免主题×字号×页面的全笛卡尔积。每张附固定产品提交、设备/系统、locale、主题、字号和合成数据说明。

| 编号 | 场景 | 必须看清 |
| --- | --- | --- |
| V1 | 成长入口及相邻模块 | 图标列、标题、副标题、统计对齐；不露财务金额 |
| V2 | 12 次完整历史总览，浅色默认字号 | 主次金额、日期、下一步、趋势/结构下钻 |
| V3 | V2 同数据深色 | 动态底色、文字、轴线与选中态 |
| V4 | 窄屏盘点输入、键盘展开 | 长名称、零、旧值日期、状态、完成/保存可达 |
| V5 | 最大辅助功能字号 | 大金额与负净资产、名称自然换行，控件不裁切 |
| V6 | 金额隐藏/锁定 | 全部数字与图形不泄露；VoiceOver 另做操作核对 |
| V7 | 空库、单次盘点（两张） | 空态聚焦，单点真实，无假数据/趋势 |
| V8 | 部分盘点、保存失败重试（最多两张） | 待补全/沿用区别，输入保留，主数不误导 |

截图必须来自运行的主 App 生产路径。Preview、静态图或独立 HTML 可用于讨论，不能代替原生验收。只使用合成数据；不要为了好看把金额和状态画死在 View 中。

独立审查回答五个问题即可：一眼能否找到净资产/日期/主操作；数字是否有明确来源和状态；图表能否回到同一次明细；与成长/体重/习惯并排是否像同一个 App；深色、大字、键盘及隐私是否可用。与范围无关的审美偏好列为后续，不扩成全 App 重构。
