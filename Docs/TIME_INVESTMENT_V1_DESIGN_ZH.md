## 一、定位与长期边界

在随心log内部新增相对独立的「时间投入」模块，先由 Owner 个人每日使用，记录阅读、学习、运动、Coding 等主动投入以及活动体验。未来妻子有明确需要时，可扩展为代两个孩子记录课外学习、运动、阅读等，但本期不开发家庭协作，也不同时开发一款独立 App。功能能脱离 AI、互联网与 Apple Intelligence 离线工作。

核心产品问题：今天把时间投入到什么活动，实际进行了多久，当次感受和补充事实是什么，过一段时间可以怎样回看？不要求每天打卡、不强制「专注/禁止手机」。开始计时后允许锁屏、切换其他 App、正常工作生活。

与睡眠模块职责分开：睡眠是作息和主观睡眠事实，不自动作为「投入」时长；与 Habit/Todo/Goal/Entry 独立，不把投入累计自动视为任务完成、习惯达标或 Quiet Wins 成果，不重复写多份事实。未来可以建立有类型的引用，但非 V1 必选。

## 二、参与者归属与数据模型契约

即使 V1 只有一名用户，核心时间记录必须拥有稳定的 participantID（真实参与者）；默认建立一个稳定本地参与者「我」。记录者/输入者与参与者为两个概念。设计可保留本地 recorder 证据或清晰的可扩展字段，但不能凭单机当前身份把这两者永久绑定，也不能为未来孩子预造参与记录。迁移/备份后 ID 应稳定，不以界面名称为身份标识。

建议独立实体（实际 SwiftData 名称按仓库规范自主决定）：
- Participant：稳定 ID、显示名、排序/归档状态；V1 界面仅使用「我」，不暴露多人管理流程。
- Activity：稳定 ID、名称、可选轻量分类或图标、归档；常用活动复用，改名不改变记录归属。
- InvestmentSession：稳定 ID、participantID、activityID、发生民用日/时区，时长或有效时间段证据、来源（计时或手工）、状态、createdAt/updatedAt、可选体验评级及备注。参与者与活动都不能仅以名称字符串代替持久 ID。
- RunningTimer：独立可恢复计时状态，保存 participantID、activityID、模式、累计有效时长、正在计时段的锚点/暂停状态、可选目标时长和版本；不把尚未完成的计时伪装成正式历史 Session。

时间字段必须区分事实发生时间、用户实际填写时间和技术更新时间。手工记录若只有「某天投入 45 分钟」，允许仅存日期和时长，不虚构 09:00–09:45；有明确开始/结束时间时才保存真实区间。计时段需要正确排除暂停时间；更改记录不能悄悄重算其它 Session。若历史时长因钟表回拨、重启或丢失锚点而无法可信恢复，应显示待用户确认/修正，而不是静默捏造精度。

完整保存、重复防护、删除、恢复与回滚语义必须独立于旧 Entry/Habit/重要日子/睡眠；不新增第二套 JSON 事实主库，复用现有 SwiftData、版本化迁移和备份。

## 三、V1 必选交互

### A. 低摩擦计时
- 选择常用活动或快速新建活动后可一键「开始」；默认正计时。
- 支持简单倒计时目标模式（例如 25/40/60 分钟），计时可暂停、恢复、结束；清楚区分「到目标」与「实际结束」。不把倒数到零时的后台停止或锁屏通知作为准确计时前提。
- 计时期间可以切换 App、锁屏和回到前台；显示基于保存的时间锚点计算，不依赖后台持续运行的定时器，不申请不必要的后台模式。
- 冷启动/系统回收/强制退出后，合理恢复正在进行的会话或要求确认异常；不能静默清空正在计时的真实数据，也不能自动补写无法证明的投入时长。
- 同一参与者默认只有一个正在进行的 Session，重复点击/多入口/重启不产生双活或重复正式记录。现阶段一个参与者，模型仍按参与者归属。
- 完成时展示简洁确认卡，实际投入时长可修改；反馈与备注可不填，确认后保存。

### B. 手工投入记录
- 不启用计时也能从「今天/历史日子」补记活动、日期、投入时长，可选起止时间和体验反馈。手工补记是正常行为，不以旧日期为错。
- 活动、时长、日期为必要信息；可选体验评价采用轻量五档/类似单击选择，补充说明可为空、之后可编辑。体验不是专业考核分数，不与时长捆绑。
- 计时得到的 Session 和手工输入的 Session 在汇总时都计入，但来源明确标注，避免两条同活动/重叠时间的误计；可以提醒疑似重复，不强制合并。
- 提供正常编辑、取消、删除（带确认）、保存失败保留草稿/原事实和重开持续可见。若用户只是看一眼/只改备注，不重置事实时间。
- V1 不强制标签树、习惯目标、番茄钟复杂规则、每日最低时长，也不要求照片才可保存。

### C. 历史与基础回顾
- 支持最近 7/30 天及活动维度的累计时长、记录次数、按日趋势和原详情回跳；汇总是描述投入，不输出 AI 结论或「投资效率评分」。
- 空日/未记录不等于零投入事实；有记录显示其真实数值。计时与手工来源可识别、按参与者隔离聚合；V1 默认只有「我」。
- 历史清单紧凑，活动名称可查找/筛选，已归档活动的历史仍能正确显示。时间跨午夜明确归属（实际活动日/开始日由本版固定并可解释），不凭时区旅行挪动原事实。

## 四、页面集成

保留 Today/Timeline/Record/Growth/Library 五 Tab，Record 仍直接打开图文记录，Today 体重/睡眠/目标/重要日子原优先级与快捷操作不改变。Growth 增加同级「时间投入」管理入口，提供活动选择、开始计时、手工补记、历史/回顾。

Today 只在有进行中计时或可明确提高频次时出现一条紧凑状态/快捷入口，不添加大面积常驻图表，不强行改写首页已有区块。独立计时面板不占用全局 Record 草稿；中途切 Tab/打开通知/其他编辑器不会丢失原草稿。

首次仅提供一条可关闭的上下文说明，例如「可以切换其他 App，计时仍按经过时间继续」，不弹长向导。界面中文优先，同时保留英文、浅深色和动态大字体、可触达按钮、VoiceOver 基础标签。

## 五、明确不做

- 家长代两个孩子的 UI/档案/监护与反馈角色工作流、家庭协作/共享/账号体系、多机同步、云服务、独立新 App。
- 专注锁机、后台监听 App 使用、屏幕使用时间自动采集、自动识别活动、Apple Watch/HealthKit、Live Activity、复杂桌面 Widget、音视频记录、AI 推荐/评分。
- 强制每个 Session 关联 Todo/Habit/Goal/Entry 或自动把投入标记成 Habit 完成；独立时间投入数据不能污染睡眠和 Quiet Wins。
- 高级可视化仪表盘、无限重叠时段约束引擎、复杂计费/项目工时结算/多人排班。

## 六、迁移、备份与隐私不变量

以真实最新版 V13/v9 为基线核对后添加下一明确 Schema/备份版本，冻结所有历史模型/包契约。测试从原使用中的可支持旧 Schema 直接覆盖到新版本，以及已有 V13（含睡眠、重要日子）的库覆盖，验证原 Entry/图片、Habit、Weight、Todo、Quiet Wins 依赖、重要日子、睡眠、外部来源等事实不变。新包恢复到隔离空库并重开，保持 participantID/活动身份/计时或手工证据/反馈；破损文件、重复ID、非法时长安全拒绝，不静默丢弃。

主 Bundle ID、存储路径、App Group、现有 Share 与 ImportantDaysWidget、Xcode Cloud workflow/签名配置不改变。测试使用合成数据库；不能触碰 Owner 真机私人库，也不在 Git 日志/诊断写入个人活动文本/反馈。

## 七、V1 验收门槛

S1：一键开始→切到其他 App→回来→暂停/继续/结束→保存，时长合理且无双活。
S2：计时中锁屏、应用后台、重启、系统终止、恢复；无法确认时提示纠正，不虚报。
S3：倒计时到目标与实际停止分开；暂停段不累计、跨日/时区/夏令时/回拨异常不造时长。
S4：手工补记纯时长、可选具体时间、体验五档/备注后补、编辑/删除/撤销草稿与失败恢复。
S5：参与者默认为我但 ID 独立、备份稳定；Activity 改名、归档不修改历史事实。
S6：7/30 日按天/活动汇总与来源回跳、空日无虚构、重复或交错 Session 处理明确。
S7：V13及旧历史库覆盖升级、备份恢复/重开、迁移失败不清库或牺牲已完成保护副本。
S8：五Tab/Record/Today/Weight/Sleep/Todo/QuietWins/ImportantDays/Share/Widget 联合冒烟，权限、构建身份保持。
S9：中文/英文、Dark/Light、较大字体与基本无障碍、单手可用。
S10：最后固定干净提交的 Debug/unsigned Release 构建、真实独立 Reviewer 复核、普通推送 Draft PR；后续 iPhone、签名与发行严格为 Owner Gate。
