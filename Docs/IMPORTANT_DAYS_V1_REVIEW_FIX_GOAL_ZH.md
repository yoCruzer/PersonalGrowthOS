## 3. 必修 R1：用户选择的纪念期次不随时钟漂移

位置（4e）：`ImportantDayViews.swift:121–144、170–183、229–257`；相关保存入口见 `QuickCaptureView.swift`。

反例：2020-10-15 起始的年度日子，2026-10-15 开启指定年份，接受默认 2026、不滚动 Picker，开始写记录；跨午夜或次日前台恢复后保存。原 `occurrenceYear=nil` 导致下一期重新计算为 2027，保存闭包可能写错期次。

成功标准：用户开启明确期次选择时，默认可见年份不能只是随时漂移的占位；在发起写记录、关联已有记录或相关 Todo 操作时，固定日子 ID 与本次明确期次日期（普通关联为 nil），后续提交使用固定操作上下文。展示的“今天/还有几天”仍可刷新，但不能改写正在进行的操作意图。

采用最小局部状态结构，不持久化全套编辑会话、不重做导航。保存时重新检查目标存在、未归档及本次操作的日期语义；如果期间发生真实规则变化使当前操作需要重新确认，保留草稿并给出明确恢复路径，不能悄悄换成新期次或偷偷丢掉关联。仅更改名称、说明、外观/Today/提醒偏好或时钟变化，不应误报成日期变更而阻止保存。

不自动改写已经保存的历史期次。特别不能给启动/导出校验增加“所有历史期次必须符合当前日子规则”的限制，导致用户改过日期后无法启动或备份。新 Entry 的 occurredAt 继续沿用原“记录当下”规则，不回填为纪念年份。

回归：默认年份跨日→保存/重开；明确历史年份正对照；普通关联 nil；农历年末跨公历年；取消再开按新选择生成上下文；三种入口均核对。优先用注入时钟/生产状态控制器触发参考日期更新，再以关键 UI 证明实际入口读取该状态，不等待真实午夜、不修改真实设备时间。

## 4. 必修 R2：关联减少后始终保有可用筛选

位置（4e）：`ImportantDayViews.swift:127–131、186–198`。

反例：两条普通关联 + 一条特定期次关联；筛选到该期次，再解除其最后一条关联。`periods=[]` 隐藏 Picker，但旧 filter 继续排除普通记录，当前页面无恢复入口。

成功标准：具体期次消失时规范化当前选择为“全部”等明确可用状态，或保留可复位入口；存在的有效期次和用户仍有效的筛选不无故重置。不要求退出重进，不用复制/重新插入记录掩盖可见性错误。

回归：留在原页解除最后一条特定期次关联，普通记录立即可见；删除对应 Entry；另一个期次仍存在；当前有效期次不变；最终全部关联为空显示真实空态。测试覆盖生产视图选择状态/接线，不只证明 unlink 服务成功。

## 5. 必修 R3：历法切换不能留下隐藏的无效标志

位置（4e）：`ImportantDayViews.swift:327–341、448–484`；`ImportantDayDate.swift:70–82`。

反例：2023 年闰二月初一的合法农历日子→切公历并确认；公历数字有效，旧 `isLeapMonth=true` 留下，校验失败，但公历页没有闰月开关。

成功标准：用户明确确认切换时，形成一致的目标历法草稿，清理不适用的闰月/特殊规则字段；坚持既有“按新历法重新解释月日、核对预览后确认”的语义，不悄悄改为保持同一绝对日期。不能放宽公历校验允许公历闰月，也不能静默把无效农历31号钳成30号。

保留原加载保护：已有农历日子首次加载不算用户切换、不误触确认、不重置已存 perspective。取消整个编辑不修改数据库/封面/关系；公历2月29日等真正需要用户选择的规则仍显式确认。

回归：闰月农历→公历→确认→保存→重开，字段与预览一致；普通农历正对照；公历→农历确认及无效日期反馈；取消保持原事实；已有农历与 elapsed 视角无修改打开/保存；原 preset 编辑后期次复位测试继续通过。
