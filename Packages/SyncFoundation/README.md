# SyncFoundation candidate

Offline native Swift/CloudKit codec preparation after G1. This package is **not linked to the product**, does not open a database or CloudKit container, and does not authorize deployment. P0 remains `CANDIDATE_NOT_FROZEN`; server schema, signed Development/Production access and real transport are NOT_RUN.

Each `PGMutationV1` is one immutable aggregate revision (stable typed object UUID + mutation UUID). Its canonical manifest carries dataset, causal parents, current-object dependencies, logical deletion, domain payload version and asset descriptors. Payload uses a separate `CKAsset`; history never grows one record. `PGOriginalV1` is dataset-scoped content-addressed original media. Causal closure, supported domain decoding, business-key deduplication and atomic aggregate projection remain required before publication; codec acceptance alone is not a valid business fact.

Local `SyncBinding` includes container/environment/accountHash/dataset/generation. It is deliberately not serializable. Every fence instance issues a fresh nonce, including A→B→A and cold reopen; it cannot authorize another instance. Check on the commit actor after any await. This primitive does not cancel operations, persist partitions, manage outbox/ACK, or replace SDK identity verification.

Canonical JSON rejects unknown fields, duplicate/unsorted collections, unsupported wire versions and alternate byte encodings. Domain payload is opaque original bytes; future domain decoders must explicitly support its kind/version. Existing manifest bytes must be compared with `verifyReplay` inside the eventual persistence transaction before insertion. Same mutation identity with changed bytes is a collision, never an update. Caller retains rejected raw input separately; this codec does not silently rewrite it.

Resource limits are candidate policy, not claims about CloudKit service limits: 64 KiB manifest, 16 MiB per domain payload, 25 MiB per original (current product limit), 256 parents, 1,024 dependencies/media references; encoded byte cap also applies. Limits reject explicitly, never truncate. The test suite includes a synthetic 10,000-line snapshot >256 KiB and exactly 25 MiB original. Domain validation and maximum legal actual snapshot sizing remain integration gates.

All outgoing asset paths must be caller-owned immutable staging leases retained until SDK completion. The codec rejects non-regular files/symlinks and bounds reads; it cannot prevent later writes to caller files. Incoming CKAsset data must be copied durably with its manifest before engine checkpoint. `verifyAssetsComplete` additionally verifies every original; a manifest or payload alone never implies a complete backup.

No custom query indexes: candidate transport is zone changes plus record IDs. Exact fields are exposed by `CloudRecordCodec.mutationFields` / `originalFields`, but these are only expected schema, not a server export or deployment difference. Logical tombstones carry no active payload/media/dependencies. No physical record deletion/GC is implemented.

Run: `swift test --package-path Packages/SyncFoundation --scratch-path /private/tmp/pgos-sync-foundation-build`.

Generate reproducible candidate field evidence with `swift run --package-path Packages/SyncFoundation --scratch-path /private/tmp/pgos-sync-foundation-build SyncSchema /private/tmp/pgos-sync-schema-NEW`. The output directory must not exist. `schema.json` is generated by enumerating actual synthetic `CKRecord` fields, checked against the codec declarations; `schema.sha256` binds its exact bytes. The synthetic payload/original fixture files are retained in that new directory. Output is deterministic and contains no account identity. This is **not** a CloudKit Console export, server diff, permission audit or deployment artifact.

The 16 MiB candidate payload cap is not a promise that every legal production aggregate fits. Actual domain maximums and aggregate partitioning must be validated before P0 freeze; inputs above the cap retain their local source and require an explicit future encoding/version policy, never lossy truncation. V16/v12 migration, persisted identity/epoch, same-transaction business/outbox writes, downloaded-file installation/leases, SDK scheduling/ACK/checkpoints, domain causal closure/conflict UI, media GC, backup/restore, notifications and Widget side effects are not implemented here.
